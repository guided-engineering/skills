# One row of the `ops-author` field guide

## What was done

- **The row for `verification`** in `skills/ops-author/SKILL.md`. Before:
  "Prefer `run` with a command the project already has; exit code 0 passes"
  and, beside it, "Without a command, `expect` says what to observe." Now:
  "Every check has an `id` and an `expect`, the condition that must hold. Add
  `run` when a command the project already has decides it; exit code 0
  passes" and, beside it, "`expect` is required even when the check has `run`;
  the validator rejects a check without it." Nothing else in the Skill
  changed. Commit `c8418f5`.
- **Why.** In both authoring runs of the local study the first draft left
  `expect` out of the checks that had a command. The validator rejected the
  draft with "missing required property expect" and the agent corrected it.
  The old wording can be read as if `expect` were needed only for a check
  without a command.
- **The install check can compare with a commit.** `tools/verify-install.mjs`
  takes `--compare <commit>`, so that the measured revision can still be
  checked byte for byte now that the working tree differs from it.
- **The README says which revision the numbers are about**, what changed
  since, and that the change was not measured.
